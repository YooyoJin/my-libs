# notes.md —— 原工程 DC_Fan.c 五大坑档案

> 这些是从 Y2C022S2 工程 `Hardware/DC_Fan.c`（~1100 行祖传代码）逆向分析中
> 挖出的问题。fanctrl 库的设计决策均源于对这些坑的修复。读公司代码时
> 积累此类记录，是建自己代码库最值钱的部分。

## 坑 1：注释说谎 —— "启动强转"实际是低速输出

- 位置：DC_Fan.c:720/795 `gpidFan.Output = PG_START_TIME; // 全速强转/启动强转`
- 事实：PG_START_TIME=uhFanStart=6700，按占空比换算 duty=(10000−1.25×6700)/10000
  ≈ **16%**，接近最低转速端（上限 7000=12.5%），离全速端（1500=81%）很远
- 三条独立验证：①波形极性推导 ②PV>SV 时 PID 使 Output 增大（增=减速）
  ③丢反馈搜索方向是 Output 递减到 1500（注释"全速运转"吻合）
- 教训：**注释与代码矛盾时，用数学换算和 PID 方向反推，不要信注释**

## 坑 2：强转时间注释 3s，实际 20s

- 位置：DC_Fan.c:713 `if (gucFan1OnTime >= 20) // 3) // 风扇口3s`
- 事实：gucFan1OnTime 在 OutDoorFanProcess() 中递增，该函数注册于 Timer.c
  的 1s 任务表（10ms 轮询调度），故 1 计数=1 秒，阈值 20=**20 秒**
- 教训：**定时逻辑必须追到调度链路最底层才能报时间**，注释里的时间不可信

## 坑 3：双写竞争 —— Output 被主循环和中断互相覆盖

- 位置：Int1_tirg()（主循环每圈调用）与 IntTca0()（512µs 中断）都写
  gpidFan.Output 并调用 Out_FanPWM()
- 后果：启动 20s 强转期内，PWM 在强转值与 PID 值之间抖动（碰巧能跑）
- fanctrl 修复：状态机单写者原则（Idle/StartupHold/Running/Search 各有唯一输出写者）

## 坑 4：PG_HALF_TIME 与 PG_START_TIME 是同一个变量

- 位置：Par.h:285-286，两个宏都指向 uhFanStart
- 后果：代码里"3s 后切半速"逻辑实际什么也没切；注释一个写"半速"一个写"全速"
- 教训：**移植旧平台时同名不同义的宏要逐一核对**（这俩来自 250×32 旧刻度体系）

## 坑 5：复制粘贴式双风机实现

- 位置：IntTca0() 内风机 1/2 两段各 ~110 行几乎逐字重复（只差 `_2` 后缀）；
  另有 65 行整段注释掉的旧 Int1_tirg、3 个空壳函数（InitDC_Tc023 等）
- 后果：改一处漏一处是必然结局
- fanctrl 修复：FanCtrl 实例化，`FanCtrl fan[2]` 一份代码双风机

## 附：量纲换算速查（反向刻度）

```
duty(千分比) = (10000 − Out×5/4) / 10     [PWM 周期计数 10000, 2kHz 载波]

Out:  0    100   1500        6700   7000   8000
duty: 1000‰ ~99‰  812‰(全速)  162‰   125‰   0‰(停)
```

刻度体系来源：旧 MCU T02 定时器（最大 250 步）×32 = 8000（Par.h 注释
"250*32=8000"），移植到 HC32 后换算系数 5/4 是两套刻度的弥合产物。
